20 给 LVGL 界面添加中文字体和图片

字体和图片既可以“装进程序”，也可以作为文件随系统发布。先选对路线，再谈转换参数。

学习目标​

  • 分清编译进程序的资源与运行时文件资源。
  • 为实际中文文案制作 CJK 字符子集，避免缺字和无谓膨胀。
  • 验证图片颜色格式、透明度、文件加载和缓存行为。

前置条件​

  • 已完成 19 让 LVGL 持续刷新，显示、触摸和主循环运行稳定。
  • LVGL 已固定为 9.4.x，显示颜色格式和 lv_conf.h 已确认。
  • 已准备有授权的字体、原始图片和最终会显示的 UTF-8 文案清单。

资源放在哪里​

方案优点代价适合
编译进程序启动简单，不依赖文件路径可执行文件变大，换资源要重新编译Logo、少量图标、固定小字库
作为文件加载资源可单独替换需要文件系统、解码器和正确安装路径大图、主题资源、经常更新的内容

对字体来说，生成的 C 字库会随程序链接，字体文件则需要对应字体引擎；对图片来说，C 数组会随程序链接，图片文件则需要 LVGL 文件系统和对应解码器。

中文字体不要一开始就塞入完整 CJK 字库。先收集界面实际文案，再生成所需字符子集；新增文案时同步更新字符清单。出现方框通常表示字体没有那个字形，不等于 UTF-8 一定损坏。

图片还要核对颜色格式、透明通道和字节顺序。编译进程序的图片跟随可执行文件；文件图片通常需要读取和解码。缓存能减少重复加载，却会占用更多 RAM；资源文件被替换后，还要考虑旧缓存失效问题。

操作步骤​

  1. 准备环境与版本信息。
  2. 执行本节操作并保存完整命令与日志。
  3. 按验收标准验证结果。

验收标准​

  • 字体、图片的来源、授权、版本和转换参数均已记录。
  • 中文测试文案没有方框或错字，字符子集与实际文案一致。
  • 编译型资源已进入目标程序，文件型资源已进入约定安装位置。
  • 图片颜色、透明区域和方向正确，冷启动后仍能加载。
  • 缓存策略及其 RAM 影响有记录，程序和资源体积已经对比。

常见问题​

现象优先检查
中文显示为方框字体是否包含对应字形，源文件是否为 UTF-8
编译时报字体或图片符号未定义生成的 C 文件是否参与编译，声明名称是否一致
文件图片无法打开LVGL 文件系统、驱动器字母、安装路径和解码器
图片偏色或透明失效颜色格式、Alpha、RGB565 字节顺序是否匹配
替换图片后仍显示旧内容是否仍在使用旧固件、旧文件或尚未失效的缓存

结果说明​

本节完成后，应同时留下“能显示的结果”和“资源如何进入系统”的记录。看到一张图并不代表部署路径已经可靠。
