22 把 LVGL 9 应用集成到 Tina SDK

先让外部工程稳定通过，再把它包装成 Tina 软件包。不要一边修应用，一边猜 SDK 集成问题。

学习目标​

  • 理解外部工程、Tina package、目标根文件系统和最终固件之间的关系。
  • 为已验证的 LVGL 9 工程补齐 Config.in、软件包 Makefile 和安装内容。
  • 从软件包编译一直验证到固件上板运行，确认结果没有倒退。

前置条件​

  • 21 检查界面性能和稳定性 已通过，独立运行的 LVGL 工程及测试结果已经归档。
  • Tina SDK 能使用课程板级配置正常编译、打包和烧录。
  • 已找到当前 SDK 中一个结构相近、能够正常构建的软件包作为模板。

集成路线​

外部工程通过 → 研究相邻软件包 → 增加 package → 选择软件包 → 安装进根文件系统 → 生成固件 → 上板验收。

Tina SDK 的目录会随版本和厂商修改而变化。本节不预设具体路径：应先从当前 SDK 的菜单入口和相邻软件包反查真实位置，再记录到项目文档，不能照搬其他 SDK 的目录。

文件或阶段主要职责必须说清楚
Config.in是否显示、如何选择、依赖什么菜单名称、依赖条件、默认状态
软件包 Makefile来源、版本、编译和安装规则使用的 LVGL 版本、交叉编译参数、安装清单
目标安装阶段把运行所需内容放进根文件系统程序、动态库、字体、图片、配置和启动方式
固件验收证明最终设备使用了新软件包固件版本、文件证据、启动日志和实际画面

集成时只解决“如何进入 SDK”。外部工程尚未通过的显示、触摸、Timer、字体或性能问题，应回到对应章节处理，而不是在 package 规则中偷偷打补丁。

操作步骤​

  1. 准备环境与版本信息。
  2. 执行本节操作并保存完整命令与日志。
  3. 按验收标准验证结果。

验收标准​

  • 外部工程的显示、触摸、Timer、资源和性能基线在集成前全部通过。
  • package 菜单入口可见，依赖、LVGL 版本和源码来源明确。
  • 软件包能够重复构建，且没有误用主机头文件、库或工具链产物。
  • 程序、运行库、字体、图片和配置均进入目标根文件系统的约定位置。
  • 新固件可以生成并烧录，板端启动日志能证明运行的是本次版本。
  • 上板后功能与基线一致，改动清单和回退方法已经归档。

常见问题​

现象优先检查
菜单中看不到软件包Config.in 是否被上级菜单包含，依赖条件是否满足
外部工程能编译，package 失败是否正确继承交叉工具链、sysroot、编译和链接参数
编译成功，根文件系统没有程序目标安装阶段是否执行，安装清单是否完整
板端提示找不到程序或库安装路径、动态链接器、运行库和目标架构
字体或图片在板端丢失文件资源是否随 package 安装，运行路径是否一致
烧录后仍是旧版本软件包是否被选中、固件是否重新生成、烧录文件是否正确

结果说明​

“package 编译成功”只是中途结果。只有程序进入根文件系统、固件重新生成并在板端通过功能与版本核对，才算完成 Tina SDK 集成。
