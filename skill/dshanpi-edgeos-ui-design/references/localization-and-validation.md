# 多语言、字体与验证指南

## 支持语言与索引

保持 `dshanpi_language_t` 的既有顺序：

| 索引 | 枚举 | 语言 |
| --- | --- | --- |
| 0 | `DSHANPI_LANG_ZH_CN` | 简体中文 |
| 1 | `DSHANPI_LANG_ZH_TW` | 繁体中文 |
| 2 | `DSHANPI_LANG_EN` | English |
| 3 | `DSHANPI_LANG_JA` | 日本語 |

部分源码表采用 `[language][item]`，部分翻译 helper 的行采用 `[English, 简中, 繁中, 日文]`。修改前先确认函数如何把 enum 映射为列，不能仅凭数组外观追加字符串。

## 文案规则

- 所有用户可见文字必须本地化：标题、按钮、选项、空状态、占位、Toast、错误、确认说明、进度阶段和可访问标签。
- 品牌、协议和标准名保持一致，如 DshanPI、CanMV、K230、UART、VAXP、Wi-Fi、OTA、RTSP、RTMP。
- 使用简短动词描述按钮；描述文字说明结果或风险。
- 错误文案避免只写“失败”，应指出对象和可执行下一步。
- 不把完整句子通过多次字符串拼接翻译；不同语言语序不同。
- 格式化字符串的占位符数量和类型在四种语言中必须一致。

## 字体选择

- English 使用 Montserrat；中文、繁体和日文使用 `ui_font_source_han_20`。
- 动态设备内容如 SSID、路径、模型文件名可能混合语言；使用覆盖所需字符的字体，或明确限制输入字符集并提供替代显示。
- 终端正文和数值可采用英文字体，但本地化标签不能因局部等宽需求切回缺少 CJK 的字体。
- 字体对象必须保持到 UI 对象销毁之后，不能加载到临时栈或短生命周期 buffer。

## CJK 子集更新

`apps/ui_font_source_han_20.c` 是编译进固件的字形子集。源字体存在于 `font/SourceHanSansSC-Medium.otf` 并不意味着固件自动拥有全部字形。

新增非 ASCII 文案后：

1. 收集所有桌面 UI 源码中的可见非 ASCII 字符。
2. 对字符去重，保留简中、繁中和日文假名/汉字。
3. 更新生成命令的 `--symbols` 参数。
4. 使用生成文件头中记录的 size、bpp、LVGL include 和 font name 选项运行 `lv_font_conv`。
5. 检查生成文件名和导出符号仍为 `ui_font_source_han_20`。
6. 交叉编译并在板端逐页查看。

不要直接编辑字形位图，也不要只凭主机浏览器或截图判断板端字体可用。

## 布局适配

- 以四种语言中最长的实际文案作为布局约束。
- 标题不与返回按钮、右侧操作或状态图标重叠。
- 主按钮文案必须完整；必要时增加宽度或采用两行，不优先缩小到 12 px 以下。
- 描述允许自然换行并设置明确宽度；检查 LVGL 的 long mode。
- Dropdown 选项完整可辨，避免通过省略号隐藏关键差异。
- 日文和繁体字形的视觉高度可能与英文不同，检查垂直居中而非只对基线数值。

## 可访问性

- 关键正文与背景保持足够明暗对比。
- 不能只靠颜色表达连接、选择、成功或失败。
- 触摸目标至少 44 × 44 px，目标间留出误触缓冲。
- 图标含义不普遍时提供文字。
- 动画不应阻碍操作；持续闪烁和快速循环仅用于必要告警。
- 屏保、对话框和 overlay 出现后控制输入焦点，避免点击穿透。

- [ ] 滚动列表拖动不会触发卡片。
- [ ] 返回按钮在屏幕边缘容易命中。

- [ ] 摄像头、UART、timer、thread、fd 和动态内存均在退出路径回收。

## 实机测试矩阵

| 维度 | 最低覆盖 |
| --- | --- |
| 语言 | 简中、繁中、英文、日文各完整走查一次 |
| 启动 | 冷启动、重启、设置开机应用、异常退出恢复 |
| 导航 | 桌面滚动、应用进入、立即返回、重复进入 20 次 |
| 弹层 | Dropdown、Picker、确认框、Toast、键盘逐一返回测试 |
| 输入 | 点按、慢拖、快速甩动、边缘点击、长按 |
| 相机 | 前摄、后摄、双摄、缺少传感器、拍照/录像中退出 |
