# DshanPI EdgeOS 设计思想

## 产品定位

DshanPI EdgeOS Desktop 不是缩小版 PC 桌面，而是端侧 AI 设备的任务入口。屏幕、内存、媒体通道和触摸精度都有限，因此设计目标是让用户在最少层级内完成“选择能力、提供输入、观察结果、可靠退出”这条主路径。

## 六项核心原则

### 1. 任务优先

- 首页展示可完成的任务，不展示技术模块清单。
- 应用名称使用用户能理解的场景词，如 Face Studio、Smart Driving、UART Lab。
- 每页突出一个主操作；调试信息和高级选项保持次级层级。
- 未完成的功能不进入桌面，也不使用“即将上线”占位卡片消耗注意力。

### 2. 内容优先、控件克制

- 相机、媒体和推理页面让内容占据最大面积。
- 控件使用轻量背景、有限阴影和明确层级，避免与图像内容竞争。
- 桌面图标用柔和色块区分类别，文字和图形共同传达含义，不仅依赖颜色。
- 状态栏只保留时间、网络和关键设备状态。

### 3. 直接且可逆

- 触摸后立即给出视觉反馈。
- 普通设置直接保存或明确提示需要重启；不可让“已选择”和“已生效”混淆。
- 删除、关机、重启、进入烧录模式等高影响操作必须二次确认。
- 可恢复失败提供重试或返回；不可恢复失败明确说明当前系统是否仍安全。

### 4. 状态诚实

- 空闲、扫描、连接、下载、校验、写入、完成和失败必须是不同状态。
- 不用无限旋转动画掩盖没有进展的任务。
- 状态文案说明正在发生什么，而不是只显示“处理中”。
- 仅在底层操作成功后展示成功；保留有助于用户行动的错误原因。

### 5. 资源感知

- 摄像头、显示层、编码器、UART 和 OTA 都视为独占或受限资源。
- 页面退出和外部应用启动是资源所有权转换，不只是视觉切页。
- 重用预创建 UI 对象降低碎片，但所有短生命周期状态必须在重新进入时重置。
- 动画、阴影和大图只在不影响实时预览、触摸响应和启动时间时使用。

### 6. 本地优先、安全兜底

- 基础桌面、设置和设备控制在无网络时可用。
- 网络能力明确呈现离线、证书、超时和服务器错误。
- OTA、密码与设备控制采用失败关闭策略；不能为了“看起来可用”而降级安全验证。
- 用户始终知道返回桌面、取消操作或恢复当前可启动系统的方法。

## 信息架构

整体信息架构分为四层：

1. 桌面：日常任务和系统状态。
2. 应用首页：任务配置与主操作。
3. 聚焦工作区：相机预览、绘画画布、终端、媒体或推理过程。
4. 临时反馈层：Picker、dropdown、对话框、Toast、加载与确认。

临时反馈层不能成为隐藏页面之外的孤立状态。任何页面退出路径都必须同时收回其临时反馈层。

## 一致性与差异化

一致性应覆盖：返回位置、触摸尺寸、字体层级、状态语义、确认方式和错误恢复。应用色彩与内容布局可以反映任务特征，但不应改变基础交互语法。

新增视觉风格前先回答：现有组件为何不足、差异是否帮助识别任务、是否能在四种语言和真实触摸屏上稳定工作。
