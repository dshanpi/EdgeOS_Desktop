# 29 接入摄像头应用

这一章把 Camera 接到 **MPP VI→VO 硬件预览 + LVGL 透明叠加**：视频由显示硬件输出，LVGL 只绘制标题、状态和拍照按钮，不再持续转换、复制摄像头画面。

沿用前面的 AI Agent 和设备连接环境。学习顺序是：检查视频节点、建立 MPP 链路、配置透明 UI、验证拍照与退出，最后部署。不要把“出现 Camera 图标”或“有 `/dev/video0`”当作适配完成。

![MPP 视频与 LVGL 控件的实机合成画面](./images/edgeos-camera-mpp-composite.png)

*截图来自 `v1.3.0-mpp` 的显示控制器 writeback，包含真实 VO 视频和上层 LVGL，不是设计稿或主机拼接。画面方向随当前镜头安装方向变化。*

## 2. 参考 SDK 建立 VI→VO 链路

SDK 根目录为 `~/100ask-course/sdk/tina-v853-100ask`，重点参考：

| SDK 位置 | 学习内容 |
| --- | --- |
| `external/eyesee-mpp/middleware/sun8iw21/sample/sample_virvi2vo/` | VI、ISP、VO 的创建、绑定、启停与错误清理 |
| 同级 `sample_virvi/` | `GetFrame()` 和 `ReleaseFrame()` 的配对使用 |
| 同级 `sample_takePicture/` | 后续 JPEG 编码的参考；本版仍保存 BMP |
| `external/eyesee-mpp/system/public/display/hwdisplay.c` | 显示图层管理、截图以及显示设备生命周期 |

本版实际使用的链路是：

~~~text
Sensor → ISP → VI(VIPP 0)
                 ├─ 虚拟通道 0 → SYS_Bind → VO → 视频层
                 └─ 虚拟通道 1 → 点击拍照时取一帧 → BMP

LVGL → ARGB framebuffer → UI 层
视频层 + UI 层 → 显示控制器合成 → LCD
~~~

### 预览不经过 LVGL 图像控件

辅助程序 `camera-mpp.c` 调用 `AW_MPI_VI_CreateVipp()`、`SetVippAttr()`、`AW_MPI_ISP_Run()`，创建 VI 虚拟通道和 VO 通道，然后执行：

~~~c
AW_MPI_SYS_Bind(&vi_chn, &vo_chn);
AW_MPI_VI_EnableVirChn(0, 0);
AW_MPI_VO_StartChn(0, 0);
~~~

程序收到 VO 的首帧渲染事件后才向 UI 报告就绪。`camera_backend.h` 只传递启动参数、拍照请求与状态，不接收视频像素；`camera_ui.h` 中没有用于显示视频的 `lv_image`。

这与旧版“V4L2 取帧 → CPU 转 RGB → LVGL 绘图”不同。旧版用于验证采集与保存链路，已被当前硬件预览替代。

~~~text
请参考 sample_virvi2vo 实现 MPP VI→VO 绑定，不再使用 CPU 转换后的
视频帧作为 LVGL 图片刷新。保留 ISP 和真实错误反馈。
不要照搬示例关闭原有 UI 图层的代码，也不要切换 LCD 输出模式。
初始化失败时按已完成的阶段清理资源，不能留下半启动的相机。
~~~

## 3. 让 LVGL 只在预览区域透明

仅设置一个控件的透明度并不够，透明信息必须贯通 LVGL、framebuffer 和硬件图层。

| 层级 | 本版设置 | 作用 |
| --- | --- | --- |
| LVGL 输出 | `LV_COLOR_FORMAT_ARGB8888` | 保留每个像素的 Alpha；原来的 XRGB 不适合此用途 |
| 相机页面 | 根背景及底层背景透明，窗口外绘制不透明区域 | 只让预览窗口露出下层视频 |
| UI 硬件层 | 逐像素 Alpha，位于视频之上 | 按钮和标题仍清晰可见 |
| VO 视频层 | 独立窗口，低于 UI 层 | 硬件输出相机图像 |

本板实测视频位于 `ch[0]/lyr[0]`、`z[0]`，UI 位于 `ch[1]/lyr[0]`、`z[16]`。这不是所有板子的固定映射，更换设备后应重新查询。

预览窗口按当前显示尺寸计算，保持相机画面比例；采集尺寸与屏幕布局分开。不能把整个 UI 图层调成半透明，否则按钮、文字也会变淡。

实测 framebuffer 中，预览中心 Alpha 为 **0**，标题区域为 **255**，“MPP LIVE” 标识背景为 **220**。合成截图中，标识覆盖在视频之上，说明不是仅把两个区域并排绘制。

~~~text
请核对当前 framebuffer 的像素格式和硬件图层顺序，把 LVGL 输出改为
ARGB，只在预览区域透出 VO；页面其他区域和触摸控件保持正常。
分别检查透明区域、标题区和视频上的半透明标识，提供 Alpha 取样与
硬件图层状态。横向和竖向布局都按实际显示尺寸计算。
~~~

## 4. 拍照与预览分开

点击 **Take photo** 后，辅助程序临时创建并启用 VI 虚拟通道 1，通过 `AW_MPI_VI_GetFrame()` 取得一帧，保存后调用 `ReleaseFrame()`，最后关闭并销毁该拍照通道。

预览继续走已经绑定 VO 的虚拟通道 0，不会为了拍照切回 CPU 连续预览。当前仍需要对拍摄的单帧进行像素转换，输出 BMP；这不等于预览链路经过 CPU，也不等于已经接入 JPEG 硬件编码。

照片保存到 `/mnt/UDISK/edgeos-camera/photos/`。保存前核对数据分区挂载和可用空间，使用唯一文件名，写入失败显示错误。进入 Camera 不会自动拍照。

~~~text
请点击拍照，确认 VO 预览保持运行；检查新文件，传回主机解码，
并比对两端哈希。验证后确认拍照虚拟通道和帧已释放。
不要只检查“Saved”提示，也不要把旧照片当作本次结果。
~~~

### 返回桌面不能只隐藏预览窗口

退出时先停止 VO 和 VI 虚拟通道、解除绑定，再销毁通道、关闭 ISP 和 VIPP，最终回收辅助进程。否则视频层可能留在桌面下方，摄像头也可能继续工作。

这份 SDK 的 `/dev/disp` 释放行为会关闭 LCD。辅助进程退出后，主程序会重新使能 LCD 并恢复 framebuffer 图层。因此目前返回存在短暂的显示恢复过程，**不是完全无闪烁切换**。若后续要消除它，可继续将显示管理改为应用生命周期内常驻复用，但不能通过省略相机资源清理掩盖问题。

相机运行期间不触发自动调暗；退出后恢复原有设置逻辑。辅助进程单次运行保护上限为一小时，到期可重新进入。当前没有完成断电启动验收。

## 6. 用正确的证据验证效果

### framebuffer 截图不等于屏幕合成结果

`/dev/fb0` 只保存 LVGL 图层。透明区域里没有相机像素，所以直接拉取它会漏掉 VO，不能据此判断相机黑屏，也不能在主机拼上照片后冒充实机截图。

本次通过显示控制器 writeback 读取合成输出。在启用 IOMMU 的系统上，使用 **DMA-BUF + `DISP_CAPTURE_COMMIT2`** 导入缓冲区。前期尝试直接传物理地址得到全黑数据并触发地址映射告警，已改用 DMA-BUF；该失败结果没有用作成功证据。

~~~text
请检查 VI→VO 首帧事件、视频层与 UI 层状态，并采集合成输出。
反复进入、退出相机，确认视频层和辅助进程都被释放，桌面仍可操作。
再回归 Settings、Drawing 和拍照；记录性能采样方法与限制。
不要把 LCD 刷新率或请求帧率写成已经测得的相机实际帧率。
~~~

目前已确认：

- MPP 首帧渲染事件正常，两个硬件图层同时启用，合成截图包含视频和控件。
- 独立通道拍照、BMP 解码、返回桌面和 LCD 恢复完成实机检查。
- 正式程序连续进入、退出 Camera **10 次全部通过**。每次退出后视频层消失、MPP 辅助进程退出，桌面进程回到单线程；这是短周期回归，不等同于长期无泄漏证明。
- 向本次相机辅助进程发送 `SIGTERM` 模拟中断后，UI 提示重试；点击 **Retry** 再次收到 VO 首帧事件，视频层恢复。未模拟全部硬件故障。
- Camera 退出后，实机 Settings 卡片页、Drawing 画布及返回桌面显示正常。本次检查页面切换与渲染，不代表重新验收了全部设置业务功能。
- 主机横、竖向布局各执行 5 轮，检查透明中心、不透明标题、按钮边界及与 Drawing 的切换。它不替代另一种实体屏幕测试。
- 请求采集速率为每秒 30 帧；本板 LCD 状态约 29 Hz。这两个值都不等于已经测得端到端视频帧率。
- 一次约 10 秒预览采样中，UI 与 MPP 进程合计约占单核 CPU 的 9.5%；只说明该场景下的进程开销，尚未与旧版在相同场景做严格对比。

实机触摸测试采用 evdev 注入，不等同于完整的物理手指验收。第二路摄像头、录像、JPEG 编码、图像质量标定和长时间压力测试不在本次完成范围内。
