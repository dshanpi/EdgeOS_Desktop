## 2. Wi-Fi 扫描与配网

![真实热点扫描列表](./images/edgeos-settings-style-wifi.png)

### 复用现有服务

板端已有 `wifi_daemon` 和 `wpa_supplicant`，启动脚本负责进入 STA 模式。现有 SDK 的 `CONNECTED` 事件会启动 DHCP 处理，因此设置页不再创建第二个 supplicant，也不通过 `killall udhcpc` 争抢网络管理权。

本轮实际控制 socket 为：

~~~text
/etc/wifi/wpa_supplicant/sockets/wlan0
~~~

后台任务使用 Unix domain socket 调用 `STATUS`、`SCAN`、`SCAN_RESULTS`、`ADD_NETWORK`、`SET_NETWORK`、`SELECT_NETWORK`、`DISCONNECT`、`REMOVE_NETWORK` 和 `SAVE_CONFIG` 等协议命令。扫描先订阅事件，收到 `CTRL-EVENT-SCAN-RESULTS` 后才读取新结果；不能把发送 `SCAN` 返回 OK 当作扫描已经完成。

扫描结果最多展示 20 个不同名称的网络，重复 SSID 合并；SSID 中的转义字节会解码，隐藏 SSID 使用“Add hidden network”。WEP、企业认证和仅 WPA3 的网络不会被误判为开放网络，选择后提示当前不支持。

~~~text
请通过设置 UI 触发 Wi-Fi 扫描，等待扫描完成事件，保存页面和日志。
随后用 SDK 的 wpa_cli 对照 scan_results，核对 SSID、信号强度和安全类型。
不要连接未授权热点，不要伪造列表；扫描为空、超时和控制接口不可用要明确区分。
日志不记录密码；截图时不要输入或展示真实密码。
~~~

功能接入阶段首次扫描曾为空，独立 `wpa_cli` 当时也只有表头；再次扫描后取得真实热点，信号约为 `-88 dBm`。本次风格优化复测时，扫描取得 11 个网络，截图中的 `Programmers` 为 `-62 dBm`，与同次 `wpa_cli scan_results` 一致。数量和信号取决于现场环境，不能用历史结果代替当前扫描，也没有用模拟热点替代实机截图。

### 密码输入与连接状态

![选择热点后的密码输入和软键盘](./images/edgeos-settings-style-wifi-dialog.png)

连接操作包含以下约束：

- SSID 校验 1～32 字节，WPA/WPA2-Personal 密码校验 8～63 个可打印 ASCII 字符。
- 密码始终遮罩；不通过 Shell 拼接或进程参数传递，也不记录到 UI 日志。
- 密码经控制 socket 交给 supplicant；临时缓冲在使用后清除，取消对话框时清空输入。
- 连接使用新网络配置，失败时删除本轮新配置并尝试恢复原活动配置，不清空其它已保存网络。
- `wpa_state=COMPLETED` 表示无线关联完成；IP 单独展示，没有 IP 时不显示“上网成功”。即使取得 IP，也不能据此证明互联网可达。
- 成功后请求 supplicant 保存配置，并将配置文件权限限制为 `0600`。保存失败与关联失败分别提示。
- 同时只允许一个 Wi-Fi 后台任务；LVGL 对象只由主线程更新，离开页面不会让工作线程访问已经释放的控件。

本轮只实测了选择热点、键盘显示、空密码拦截和取消。没有取得用户授权热点的实际凭据，因此真实认证、DHCP、保存后重连及忘记活动网络仍需要在板端完成以下验收：

~~~text
我将在开发板屏幕输入测试热点密码。请不要读取、截图或回显密码。
输入完成后，请观察连接状态、IP 和服务日志，确认配置保存权限。
在我同意断开后验证断开、重新连接，以及明确确认后忘记该测试网络。
报告无线关联、IP 获取、互联网连通和持久保存各自的结果，不合并成一个“成功”。
~~~

## 3. 背光与自动调暗

![显示和自动调暗设置](./images/edgeos-settings-style-display.png)

### Tina 特有的文件描述符生命周期

本板没有标准 `/sys/class/backlight` 节点。Agent 从 SDK 确认 `/dev/disp` 的 `DISP_LCD_SET_BRIGHTNESS`、`DISP_LCD_GET_BRIGHTNESS`，使用驱动原始值与 UI 百分比换算，并设置 5% 下限。

第一版采用“打开、读写、关闭”的方式，实机暴露了重要问题：该 SDK 的 `disp_release()` 会禁用显示图层和 LCD，关闭文件描述符就可能让物理屏幕熄灭。此时 framebuffer 仍可能含有正常画面，**单看截图不足以证明 LCD 正常输出**。

修正后的程序在进程生命周期内保持一个显示设备描述符，不在每次读写后关闭；启动时恢复 LCD 输出，重新配置 framebuffer 图层。复测同时核对：

1. UI 滑块触发的日志。
2. ioctl 返回的亮度回读值。
3. `/sys/class/disp/disp/attr/sys` 中的 `lcd output`、backlight、帧率及 `BUF enable`。
4. framebuffer 实图。

实测将亮度设为 53% 时请求原始值 `135`，回读同为 `135`；随后恢复到约 20%，请求和回读均为 `51`。修正后 LCD 与图层保持启用，没有再把正常 framebuffer 当作物理显示恢复的唯一证据。

### 调暗、唤醒和保存

~~~text
请通过 UI 调整背光，逐项比较滑块值、ioctl 回读和显示驱动状态。
再测试“Dim now”和 1 分钟自动调暗，确认点击唤醒后恢复原亮度。
唤醒点击不能穿透到背后的重启或关机按钮。
验证结束恢复自动调暗为 Never，并保存偏好；不要操作 CPU suspend。
~~~

本轮两种调暗均记录 `restore_raw=51`，调暗原始值为 `13`，点击后回读恢复为 `51`。全屏唤醒层截获第一次触摸，再等待抬手，避免点击穿透。自动调暗在密码对话框或网络任务期间暂缓。

自动调暗没有停止 CPU、没有关闭 Wi-Fi，也没有验证深度睡眠唤醒链路，所以不会将它称为系统休眠。

## 4. 声音、时间与启动应用

### 声音

声音页控制 SDK 中真实的 `LINEOUT volume` 与 `LINEOUT`。操作通过固定程序和参数执行，不允许用户文本变成任意 Shell 命令。音量释放滑块后写入，再读取实际值；静音也检查开关回读。

本轮请求 50% 后，ALSA 的离散控件返回 `16/31`、约 52%。UI 因此区分请求值与实际值，不把正常量化差异当作驱动失败。静音读回 `[off]`，取消静音后恢复；测试后恢复原有满量程附近的音量。

这只验证 mixer 控件，尚未通过扬声器或耳机试听。

### 时间

可选择桌面时区和 12/24 小时显示，保存后更新桌面时钟。实现使用本进程 `TZ` 与 `tzset()`，不修改系统 RTC，不自动调用网络校时。

本轮板端系统时间仍从 1970 年开始计时，说明尚未完成系统校时；时区切换不会修复这一问题。截图和日志的测试日期以 Windows 主机记录为准，不能以板端显示年份推断测试发生日期。

### 启动应用

启动应用可选 Desktop、Settings、Drawing，由正式程序启动时读取偏好决定首页。本轮将 Settings 保存为启动目标，验证服务启动时直接进入设置分类页；测试结束后可通过 UI 改回 Desktop，而不是修改启动脚本中的硬编码参数。

## 5. 电源操作

![V853 电源页](./images/edgeos-settings-style-power.png)

电源页读取 `/sys/class/power_supply`。本轮 `battery/present=0`，因此显示“Battery: not detected”，不把 `capacity=-1` 当作电池电量；外接电源节点显示在线。

![电源操作二次确认](./images/edgeos-settings-style-power-confirm.png)

关机确认与取消已验证，但本轮没有实际切断运行中的开发板。系统深度休眠和恢复出厂没有提供入口。

## 7. 后端回归与实机证据

除板端实测外，Agent 在虚拟机独立临时目录运行了原生 C 回归测试。测试启动模拟 wpa_supplicant socket，不连接真实无线网络，不读取或修改板端凭据。
